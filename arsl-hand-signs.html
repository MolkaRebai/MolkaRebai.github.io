Real-Time Arabic Sign Language Recognition with MediaPipe and ResNet50

A learning project write-up — how I built a real-time classifier for the Arabic Sign Language (ArSL) alphabet, from hand detection to on-screen prediction.

The problem

Sign language recognition is a genuinely useful computer vision problem, but most public tutorials and datasets target American Sign Language (ASL). Arabic Sign Language has its own 31-letter alphabet, several signs that are visually close to one another, and far less off-the-shelf tooling. I wanted to see whether a fairly standard CNN architecture, combined with a proper hand-detection front end, could get real-time recognition working end to end — not just classify a static, pre-cropped image dataset.

How it works

The pipeline runs entirely on a live webcam feed:

Webcam frame
    │
    ▼
MediaPipe Hands — detects hand landmarks
    │
    ▼
Bounding box extraction — crops hand region with padding
    │
    ▼
Resize to 224×224 — ResNet50 input format
    │
    ▼
ResNet50 classifier — predicts Arabic letter
    │
    ▼
Display prediction on frame + Arabic text output

MediaPipe Hands handles the hard part first: finding where the hand actually is in the frame, independent of background, lighting, or where the signer is standing. That landmark detection gives a bounding box, which gets cropped with some padding and resized to the 224×224 input ResNet50 expects — the same preprocessing a static-image classifier would need, just run on every frame instead of once.

Model & training

DetailValue
ArchitectureResNet50 (ImageNet-pretrained, fine-tuned)
Input224×224 RGB
Classes31 Arabic letters
Training100 epochs, batch size 32
Test accuracy72.78%
DatasetArSL dataset, 1,000+ images per class

Starting from ImageNet weights rather than training from scratch matters a lot here — the dataset, while reasonably sized per class, is small by deep learning standards, and fine-tuning a pretrained backbone gets useful edge and shape features "for free" instead of having to learn them from a few thousand hand images.

Data augmentation

To help the model generalize across hand positions and lighting rather than memorizing the training set:

  • Rotation (±20°)
  • Width & height shift (±20%)
  • Shear and zoom (±20%)
  • ResNet50-specific preprocess_input normalization
  • Horizontal flip disabled — deliberately, since Arabic signs are not mirror-symmetric and flipping would create label noise (a flipped sign can look like a different, valid letter)

Being honest about where 72.78% leaves things

72.78% test accuracy across 31 classes is a solid baseline, not a production number. Random guessing across 31 classes would land around 3%, so the model has clearly learned real structure — but for a system meant to be used in practice, roughly one in four predictions being wrong matters. Several ArSL letters are visually close (differing mainly in finger curl or a single extended digit), and that's almost certainly where most of the remaining error concentrates, the same way visually similar ASL letters are the hardest pairs for English-alphabet sign classifiers.

It's also worth being clear that the reported number is held-out test accuracy on the same dataset distribution — same camera setup, similar backgrounds and lighting to the training images. Real-world webcam accuracy, with a different camera, a cluttered background, or inconsistent lighting, hasn't been separately measured, and would reasonably be expected to be lower than the reported figure until it is.

What I'd improve next

  • Build a confusion matrix broken down by letter, to find and specifically target the most-confused sign pairs rather than improving accuracy uniformly.
  • Measure real-world webcam accuracy separately from held-out test accuracy, across a few different cameras/lighting setups.
  • Add temporal smoothing (e.g. majority vote over the last N frames) so a single misclassified frame doesn't flicker the on-screen prediction.
  • Try a lighter backbone (MobileNet-class) to see how much accuracy is actually being traded for ResNet50's extra capacity, and whether a smaller model can run faster with an acceptable accuracy cost.
