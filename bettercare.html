BetterCare: A Student Portal for Therapeutic Access

A learning project write-up — the student-facing side of BetterCare, a platform aimed at making it easier for students to find and reach therapeutic support.

The problem

Getting therapeutic support as a student usually starts with friction: not knowing which therapists are available, having to reach out by phone or email to even find a time slot, and no easy way to notice a pattern in how you've been feeling over weeks rather than a single bad day. BetterCare's goal is to collapse that into one place — find a therapist, book a slot, and keep a lightweight day-to-day record, without the usual back-and-forth.

What this repo covers

This repository is specifically the student-side interface of BetterCare — the part a student actually logs into. It's built with Next.js on the frontend and Firebase for authentication and data, styled with Tailwind CSS.

  • Authentication — student sign-up and login via Firebase Auth.
  • Therapist search — browse and filter therapists by specialty or location.
  • Appointment booking — book a session directly from a therapist's profile.
  • Mood tracking — a daily check-in so a student (and, implicitly, their therapist) can see how mood trends over time, not just how it looks in a single session.
  • Messaging — a channel for student–therapist communication between sessions.
  • Resources — a section for self-help content and material outside of direct sessions.

Being upfront about scope

This repo is one half of a larger system. "Student-side interface" in the description is doing real work: the matching therapist-side app (managing availability, viewing booked sessions, responding to messages) is a separate piece, not part of this codebase. Judged purely on its own, this repo is the client experience — sign up, search, book, track, message — backed by Firebase rather than a custom backend service.

Using Firebase directly (Auth + Firestore, most likely, based on the stack) is a reasonable choice for a project like this: it removes the need to stand up and secure a separate backend just to validate the product idea, at the cost of being more tightly coupled to Firebase's data model and pricing than a custom API would be.

What I'd improve next

  • Document the Firestore data model and security rules explicitly, since that's usually where a Firebase-backed app's real correctness and privacy guarantees live.
  • Add a proper appointment-conflict check (double-booking prevention) if it isn't already enforced server-side.
  • Expose a lightweight way to see mood-tracking trends visually (a simple chart) rather than a raw daily log.
  • Write up the therapist-side app alongside this one, since the two only tell the full story together.
